# ADR-008: Design tokens as a single JSON source

- Status: Accepted
- Date: 2026-11-13
- Requirements: FR-UI-001, FR-UI-003, NFR-UX-001, NFR-PORT-001, UI/UX 6 and 8

## Context
UI/UX section 6 listed token directions only. Two renderers need the same values: the Win32 overlay/selector today and Avalonia in Phase 6. Hard-coded RGB values had already drifted (overlay `#0A0A10`, selector stock colours).

## Decision
`assets/theme/veil-tokens.json` is the only source. It is embedded in `VEIL.Domain` (`VeilTheme`, strictly validated, no UI dependency); the Windows adapter reads it through an internal `Palette`; Avalonia resources are generated by `tools/gen_axaml.py` and a unit test fails if they drift. Contrast thresholds are asserted in tests, so a colour change that breaks accessibility fails the build. Violet fills are not allowed for text (measured 3.6-3.8:1); `text.link` is the text-safe violet.

## Consequences / open items
Reference images are inspiration only and are not shipped. No light or high-contrast theme. Motion tokens were not used when this was written; since then the Focus overlay animates gently (slow glow on `pulseMs`, one drifting dot, a `slowMs` fade-in) and the selector fades in over about 160 ms. All of it stops under reduced motion or when Windows' animation effects are off. The Avalonia check harness is outside the solution and CI. Windows 10 rendering of the dark caption is unverified.
